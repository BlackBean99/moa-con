# T12 중단된 파일 보관 복구

- 반례: 이미지가 Saved로 이동한 직후 프로세스가 종료되면 DB 참조가 없고 pending/Failed에도 없어 사용자가 복구할 수 없었다.
- 복구 API가 없던 최초 검사 실패(`/tmp/moacon-orphan-red.xcresult`, 컴파일 실패). 구현 후 새 회귀 통과: DB에 등록된 파일은 Saved에 유지, 참조 없는 파일만 Failed로 이동, bytes 유지, 두 번째 복구는 0건.
- 전체 단위 31개 통과. 최종 전체 42개 회귀 통과(/tmp/moacon-release-isolated.xcresult).
- SharedImport 시작 시 먼저 DB 참조 목록을 성공적으로 읽고 복구한다. DB 조회 실패 시 원본을 이동하지 않고 오류를 안내한다. 복구된 사진은 자동으로 사용 번호를 결정하지 않고 대기 화면의 재시도/직접 입력으로 연결한다.
- 파일 상태 이동 실패 메시지는 정확한 위치를 단정하지 않고 원본 파일 보존과 저장 공간 확보를 안내한다.

- 전체 UI 회귀에서 실행마다 빈 메모리 DB를 쓰면서 이전 테스트의 Saved 파일을 공유해 실패 목록이 누적된 문제 발견. DEBUG --ui-testing 원본 저장소를 프로세스별 UUID 디렉터리로 격리했다. Release 저장소와 실제 복구는 유지한다. 격리 후 전체 42개 통과, T09에 기록.
