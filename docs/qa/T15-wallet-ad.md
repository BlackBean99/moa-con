# T15 보관함 배너 검증

확인된 사용 가능 쿠폰이 있는 보관함에만 광고를 배치했다. 확인 필요/지난 쿠폰, 빈 보관함, 온보딩, 검색 진입, 등록, 상세/원본, 스캔과 설정·삭제 처리 중에는 배너를 제거한다. 하단 시스템 검색 컨트롤과 배너 사이에 별도 여백을 두며 SDK의 기본 320×50 배너를 가운데 정렬한다. 전면·보상·앱 시작 광고는 없다.

SDK가 광고를 받았을 때만 높이를 배정한다. 실패 시 높이/여백/접근성 요소를 제거하며 사용자 쿠폰 작업에 오류 팝업을 띄우지 않는다. SDK 자동 갱신 외에 타이머 재요청은 없고, 새 보관함 진입 때 새 배너가 생성될 수 있다. 쿠폰 데이터를 받지 않는 독립 UIViewControllerRepresentable이 SDK 배너를 표시한다.

## 증거

- 네 가지 UI 과업: 보관함→등록→검색→상세→원본에서 배너 제거, 실패 상태에도 사용 완료, 온보딩/빈 보관함에 광고 없음, 최대 글자/다크 모드에서 등록 접근. 첫 검증 모두 통과(/tmp/moacon-ads-placement.xcresult).
- 실제 SDK에서 공식 샘플 앱 ID/배너 ID로 요청 성공. 받은 광고의 `Test mode` 표시와 앱 광고 표기를 스크린샷으로 직접 확인했다. 클릭하지 않았다. UI fixture가 아닌 Google SDK 요청 성공이다(/tmp/moacon-ads-sdk.xcresult).
- 초기 큰 글자 캡처에서 고정 높이 때문에 광고 표기가 잘렸다. 콘텐츠 높이를 자연스럽게 계산하고 광고 표기의 글자 확대 상한을 적용해 잘림을 수정했다. 앱의 쿠폰 글자 확대는 유지했다.
- 수정 후 관련 UI 네 개와 실제 SDK 통합 한 개 **5/5 통과**, 실패/스킵 0(/tmp/moacon-ads-final-ui.xcresult). 검토 중 배너도 제거하는 반례를 추가했다. 최종 광고·큰 글자·원본 캡처는 artifacts/release/ads-final-ui/에 있다.

SDK 통합 테스트는 네트워크에 의존하므로 자동 회귀에서 제외하고 따로 실행했다. UI fixture의 실패 테스트는 실패 상태에서 기능 유지/빈 광고 영역 제거를 검증하며 실제 AdMob no-fill 응답이나 지급 계정 승인을 대체하지 않는다. 실제 기기의 광고·지역별 UMP·iPad 화면·재방문 효과는 미검증이다. 호스트 실행 지연이 있었으므로 테스트 경과 시간을 앱 응답 성능으로 주장하지 않는다.

추가 검증: 최대 글자에서 등록 화면을 닫은 뒤 스크롤해 쿠폰을 열고 원본 버튼까지 접근하는 테스트도 1/1 통과(/tmp/moacon-ads-large-final.xcresult).
