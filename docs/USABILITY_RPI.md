# 모아콘 사용성 개선 — RPI

## Research (전문가 휴리스틱 평가)
사용자 연구 결과가 아니라 소스 기반 전문가 평가다. 심각도 4=핵심 작업 실패, 3=빈번한 혼란/복구 비용, 2=효율 저하.

| 문제 | 심각도 | 근거 | 수용 기준 |
|---|---|---|---|
| 일반 상품 바코드가 사용 가능한 쿠폰에 혼재 | 4 | 바코드 .35 + 가격 .20만으로 분류 통과 | 쿠폰 문맥 없는 바코드는 확인 필요로 분리 |
| 수동/공유 이미지가 상세에서 사라짐 | 4 | manual UUID는 PHAsset이 아니며 공유 파일은 저장 후 삭제 | 가져온 원본을 보관하고 상세에서 재사용 |
| 인식 정보 수정 불가 | 3 | 상세는 읽기 전용 | 브랜드/상품/만료일 수정과 확인 승인 |
| 권한 거부 시 보관함 접근 불가 | 3 | RootView가 수동 가져오기만 표시 | 권한과 무관하게 보관함 사용 가능 |
| 상태 혼재·검색 없음 | 3 | 전체 생성일 순 목록 | 사용 가능/확인 필요/지난 쿠폰 분리, 검색, 만료 임박 순 |
| 삭제 오작동·저장 실패 숨김 | 3 | full swipe 삭제, try? | 삭제 확인, 실패 안내 |
| 금액 설정 변경이 차감 잔액 복원 | 4 | 부분 차감 끄면 원금으로 초기화 | 설정 변경으로 잔액이 증가하지 않음 |
| 결과 피드백 오류 | 2 | 생성 시각으로 신규 건수 추측 | 정확한 신규/중복/확인 필요 집계 |
| 정체성·일상적 효용 불명확 | 2 | 일반 목록 제목과 아이콘 | 모아콘 이름, 쓸 쿠폰과 만료 우선, 명확한 행동 문구 |

## Plan
1. 분류/파싱: 바코드를 식별 키로 유지하되 쿠폰 여부와 분리. 불확실 후보는 원본과 함께 확인 필요 보관. 여러 바코드는 자동 확정하지 않는다.
2. 저장/가져오기: 원본 영구 보관, 중복 집계, 잔액 보존, 권한과 보관함 분리.
3. UI: 검색/상태/만료 정렬, 결과 안내, 정보 수정/확인, 삭제 확인, 이미지 확대.
4. Verify/ship: 회귀 테스트, 시뮬레이터 실행/화면 확인, 서명된 실기기 빌드와 로컬 설치.

## Elenchus 반증 기준
- 가격/날짜가 있다는 이유만으로 쿠폰인가? 일반 상품/영수증/멤버십 사례로 반증한다.
- 수정 부담을 없앴는가? 완전 자동화를 주장하지 않는다. 불확실성을 사용 가능 목록에서 격리하고 승인 경로를 줄인다.
- 잔액이 진실인가? 차감 후 설정 해제 및 사용 취소가 잔액을 늘리는지 검증한다.
- 재방문성이 증명됐는가? 만료 우선과 검색은 효용 가설이다. 사용자 반복사용 연구 없이 선호/습관 형성을 주장하지 않는다.
- 네이티브 배포됐는가? 빌드 성공뿐 아니라 설치/실행 명령 결과를 기록한다.

## Implementation 판단과 결과

- 바코드는 중복 식별 키이며 쿠폰 여부의 증거로 단독 사용하지 않는다. 쿠폰 문맥이 있고 바코드가 하나일 때만 자동 확정하며, 멤버십/영수증 문맥이나 복수 바코드는 확인 필요에 둔다. 통계적으로 보정된 확률 분류기가 아니라 보수적인 휴리스틱이다.
- 기존 버전은 인식 문맥을 저장하지 않으므로 오분류를 사후 자동 재판정할 수 없다. 기존 데이터를 삭제하지 않고 확인 필요로 이동한다. 새 쿠폰은 새 규칙을 적용한다. 한번 확인한 정보는 재스캔으로 덮어쓰지 않는다.
- 브랜드 사전과 교환처/사용처 문구를 사용한다. 만료일은 명시된 유효기간에서 읽고, 기간 범위의 끝 날짜를 택한다. 발행일을 만료일로 취급하지 않는다. 가격만 있는 줄과 상품명에 포함된 숫자를 구별한다.
- 확인 필요 항목은 사용 처리/차감할 수 없다. 명시적 ‘기프티콘으로 확인하고 저장’으로 승인한다. 검색과 상태 필터는 인식 수정의 부담과 실제 매장 사용 흐름을 분리한다.
- 쿠폰 삭제를 확인받고, 삭제한 바코드가 자동 스캔으로 재등장하지 않게 한다. 직접 가져오기는 다시 등록 가능하다.
- 부분 차감 설정이나 사용 상태 취소가 이미 쓴 금액을 복원하지 않는다. 차감으로 잔액 0이 된 항목의 취소는 차단하고 이유를 알린다. 잔액은 사용자가 기록한 값이며 매장 시스템과 동기화하지 않는다.
- 수동/공유 가져온 원본을 보관하고, 처리된 파일을 다시 읽지 않는다. Photos 원본이 없으면 로딩 표시를 무한 유지하지 않고 불러오기 실패를 알린다.
- 모아콘 이름, 코럴/크림/먹색 팔레트, 모은 티켓 형태의 M 아이콘, ‘모아두고, 제때 쓰세요’ 문구를 일관되게 적용한다. 앱 아이콘은 재현 가능한 벡터 스크립트로 생성한다.
- 확대 화면은 지연 렌더링되는 목록 행이 아니라 상세 화면이 소유하도록 수정했다. 화면 테스트에서 ‘열렸다가 닫히는’ 동작이 반증되어 고쳤다. 확인 승인 후 목록 필터가 바뀌어도 상세 동작을 유지하도록 값 기반 탐색을 사용한다.

## 평가 방법과 해석

핵심 사용자 과업: (1) 사진에서 쿠폰 찾기, (2) 바코드 후보 확인, (3) 매장 앞에서 검색하고 원본 제시, (4) 사용/잔액 기록, (5) 오인식 수정 및 불필요 항목 삭제.

평가 축: 시스템 상태 가시성, 현실 용어와 일치, 사용자 통제/복구, 오류 예방, 기억 대신 인식, 탐색 효율, 브랜드 일관성, 접근성, 데이터 신뢰성. Apple의 [Privacy 지침](https://developer.apple.com/design/human-interface-guidelines/privacy/)을 참고하여 보관함을 권한에 종속시키지 않고 사진 접근 목적을 설명한다. [HIG](https://developer.apple.com/design/human-interface-guidelines/)를 기준으로 네이티브 탐색·검색·확인 UI와 글자 크기 대응을 사용한다.

개선 전에는 일반 바코드가 사용 가능 목록에 들어가고, 잘못 인식된 필드를 수정할 수 없었다. 개선 후에는 별도 확인 목록에서 원본 확인→정보 수정→명시적 승인으로 복구할 수 있다. 사용자 모집/관찰 없이 작업 시간 단축률, SUS 점수, 재방문률, 브랜드 선호도를 수치로 꾸며내지 않는다.

‘자꾸 손이 가는가’의 현재 가설은 쿠폰을 많이 모으는 장식보다 **쓸 쿠폰을 빨리 찾고 만료 전에 쓰는 효용**이다. 검색, 만료순 정렬, D-day, 완료 항목 분리가 이를 지원한다. 습관 형성이나 만족은 아직 실사용 검증 대상이다.

## 실제 사용자 검증 후속 프로토콜

5~8명에게 실제 쿠폰/일반 바코드가 섞인 사진을 제공하고 위 5개 과업을 수행하도록 관찰한다. 과업 성공 여부·첫 시도 시간·오분류로 인한 사용 실수·수정 횟수·실패 후 복구를 기록한다. 사진 접근을 거부하는 사용자와 큰 글자를 쓰는 사용자를 포함한다. 1주 후 쿠폰 찾기/사용 경험과 재방문 이유를 확인한다. 실쿠폰은 개인정보 제거 후 별도 정답표로 정밀도·재현율을 계산한다. 합성 데이터 회귀 테스트를 실쿠폰 인식률로 환산하지 않는다.

## 알려진 경계

- 바코드가 검출되지 않으면 저장하지 않는다. 바코드가 흐리거나 없는 쿠폰의 수동 번호 등록은 아직 지원하지 않는다.
- 여러 바코드 중 최초 후보를 임시 저장하므로 원본에서 정확한 번호를 확인/수정해야 한다. 자동으로 실제 교환 바코드를 판별했다고 주장하지 않는다.
- iCloud에만 있는 사진은 네트워크 다운로드 없이 분석할 수 없어 건너뛴다. 최초 전체 라이브러리 스캔은 이미지 수에 비례하며 아직 증분 체크포인트가 없다.
- 기존 버전에서 이미 삭제해 버린 공유 원본과 manual UUID만 저장한 사진은 업데이트로 복원할 수 없다. 다시 가져와야 한다.
- VoiceOver 실기기 탐색, 실제 결제 스캐너 판독, 백그라운드 시스템 스케줄/배터리, 장기 반복사용은 실기기 검증이 필요하다.
- App Store/TestFlight 배포 범위가 아니라 로컬 개발 배포다. 실기기는 계정/프로파일 갱신이 필요하다.

시뮬레이터 최신 바코드 revision 3/4는 CPU 지정 후에도 합성 Code128 결과가 비어 있었고, GPU 기본 설정은 inference context 오류를 냈다. 시뮬레이터에만 CPU와 지원되는 legacy revision 1을 적용하여 같은 테스트를 통과시켰다. 실제 기기에는 이 변경을 적용하지 않는다. 이 검증을 실기기 최신 revision의 인식률로 해석하지 않는다.

빌드 로그의 AppIntents 메타데이터 추출 생략 메시지는 해당 프레임워크를 사용하지 않기 때문에 나오는 Xcode 도구 경고다. 최종 빌드에서 앱 소스의 컴파일 경고와 AppIcon 규격 경고는 없다.

로컬 시뮬레이터 배포 파일: `artifacts/usability/Moacon-Simulator-0.2.zip` (iPhone용 IPA가 아님).
실기기 재시도: Xcode → Settings → Accounts에서 재로그인 후 `./scripts/deploy-local.sh --device`.

코드 검토는 정확성·읽기 쉬움·구조·보안·성능을 대상으로 자체 수행했다. 모델 변경/중복/잔액/삭제/입력 검증은 회귀 테스트로 대조했다. 수정 폼과 확대 뷰는 별도 파일로 분리했고, 테스트 데이터는 DEBUG 전용 메모리 저장소와 격리된 임시 이미지 폴더를 사용한다. 원본·계정 정보가 포함될 수 있는 로그와 빌드 산출물은 Git에서 제외한다.

롤백은 앱을 삭제하지 않고 이전 코드로 다시 빌드·설치하는 방식으로 한다. 데이터 손실이 의심되면 이전 모델로 바로 되돌리기 전에 저장소와 로컬 이미지 복사본을 먼저 백업한다. 실제 기기 저장소 백업/다운그레이드는 이번 환경에서 실행하지 않았다.
