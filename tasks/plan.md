# 모아콘 심사 제출 직전 준비 계획

기준 커밋: 0c73eea. 작업 브랜치: feature/release-readiness. worktree: ../moa-con-release.
사용자가 요청한 네 기능을 구현하고 테스트/Archive/배포 자료를 준비한다. 실제 심사 제출 버튼은 누르지 않는다.

## 과업 관리 계약

단일 상태 원본은 tasks/todo.md다. `python3 scripts/tasks.py list|next|check`로 조회/검증한다. `start ID`, `done ID --evidence 경로`, `block ID --reason 이유`로 상태를 변경한다. 완료에는 검증 증거가 필요하며 의존 과업이 완료돼야 한다. 체크포인트 실패 시 후속 과업을 완료하지 않는다. 작업 기록은 tasks/events.md와 docs/history에 남긴다. Git 브랜치/커밋은 task ID로 연결한다. GitHub 이슈·PR 템플릿은 이 계약을 참조하며 상태를 중복 관리하지 않는다.

## 설계와 순서

1. 금액 의미·바코드 후보·원본 출처를 하위 호환 기본값으로 보존한다. 기존 금액은 임의로 재계산하지 않고 기존 부분 차감 설정을 유지한다.
2. 사진 선택 후 인식 실패도 원본을 유지한 입력 폼으로 연결한다. 다중 코드는 명시적으로 선택하고 상품 교환권/금액권을 구분한다. 상품 가격·할인액은 잔액에 넣지 않는다.
3. 공유 확장은 파일을 안전하게 저장한 결과를 보여준다. 앱은 실패 항목을 읽을 수 있는 대기열로 옮겨 재시도/직접 입력/삭제를 제공한다. 중복은 원본 중복 파일을 정리한다.
4. 자동 찾기의 새 쿠폰도 이미지 복사본을 저장한 뒤 DB에 등록한다. 기존 Photos 참조는 접근 가능할 때 복사하고 불가능하면 복구 안내를 유지한다. 라이브러리 원본은 삭제하지 않는다.
5. 만료 알림은 사용자 선택 후 승인된 미사용 쿠폰에 예약한다. 수정/사용/삭제/권한/시간대 변화에서 다시 계산한다. 저장 호출 순서를 지키고 오래된 비동기 결과가 새 예약을 덮어쓰지 않게 한다.
6. 회귀 테스트, 네이티브 QA, Release Archive, 로컬 설치, 개인정보/지원/스크린샷/심사 노트를 준비한다. 배포 Validate와 공개 URL·연락처는 실제 정보/권한에 근거한다.

## 완료 판단

코드 존재와 실제 과업 성공을 구분한다. 금액 차감, 번호 중복, 저장 실패, 원본 접근 상실, 알림 갱신을 반증 테스트로 확인한다. 실제 매장 판독·실제 쿠폰 정확도·사용자 재방문은 자동 테스트로 대체하지 않는다. 운영 정보나 배포 인증이 없으면 해당 gate만 blocked로 기록하고 가능한 작업은 계속 진행한다.

## 범위와 위험

서버·로그인·광고·분석 SDK는 추가하지 않는다. 새 이미지 복사는 저장 공간을 사용한다. 공유 이미지 크기를 제한하고 실패 자료는 사용자가 삭제할 수 있게 한다. SwiftData 추가 필드는 기본값을 주고 기존 저장소 이관을 테스트한다. 알림은 OS 권한과 실행 환경에 영향을 받으므로 전달 시각을 보장하지 않는다.

공개 정책/지원 페이지 운영자·이메일·URL과 첫 출시 국가는 사용자에게 비동기로 확인 요청했다. 답변 전에는 한국/무료/현재 iPhone+iPad 범위를 가정한 초안을 준비하고 외부 설정 완료로 표시하지 않는다.
